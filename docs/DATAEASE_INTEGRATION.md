# DataEase 接入说明

## 8 月 1 日需要确认的输入

1. 下发的是 DataEase 编辑权限、嵌入链接、查询 API、数据库连接还是文件样例；
2. 字段清单、数据类型、示例值和空值规则；
3. 广东侧、香港侧话单的关联主键及会话时间窗；
4. 鉴权方式、Token 生命周期、CORS 和允许来源；
5. 数据刷新频率、延迟 SLA、单次数据量及分页方式；
6. 数据脱敏、网络边界和对外展示限制；
7. 双方确认的指标口径、阈值和异常规则。

## 模式一：DataEase 原生大屏

直接在 DataEase 中建立数据集和大屏。Vue Demo 作为视觉原型、业务口径原型和比赛保底页面。适合主办方明确要求成果必须在 DataEase 中制作的场景。

## 模式二：Vue 外壳嵌入 DataEase

DataEase 负责图表，Vue 负责标题、导航和其他业务操作。必须确认嵌入链接、CSP、登录态和 Token 签发方式。如果 Token 需要 Secret 生成，必须由后端代理签发，不能在 GitHub Pages 中完成。

## 模式三：Vue 通过安全 API 获取数据

后端服务读取 DataEase 或数据库，将数据转换成 `DATA_CONTRACT.md` 约定的 View Model。Vue 继续使用现有组件。这是交互自由度最高、边界最清晰的模式，但需要可部署的后端或 Serverless 层。

## 静态前端限制

- GitHub Pages 无法安全保存 DataEase APP Secret 或数据库密码；
- `VITE_*` 变量会进入公开构建产物；
- 浏览器不能直接连接生产数据库；
- 私有 API 必须正确设置 CORS，并通过短期凭据或后端会话鉴权；
- 不得为了快速演示将永久 Token 硬编码进 JavaScript。

## 适配步骤

1. 将正式样例映射为统一 Dashboard View Model；
2. 对流量单位、时区、漫游方向、金额精度和空值进行归一化；
3. 使用现有单元测试核对 KPI 与图表总数一致；
4. 增加正式数据源健康状态与安全回退；
5. 在测试环境验证筛选、联动和刷新；
6. 完成数据脱敏与公开页面安全复核后再部署。
