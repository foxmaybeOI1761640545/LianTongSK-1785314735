# 大屏真实数据接入与指标溯源

## 1. 适用范围

本文对应 `onecard_ps_roam_202607.xlsx`、`结论.docx` 与当前 Vue 大屏。页面只发布脱敏后的静态聚合及 `前三位 + **** + 后四位` 号码，不包含完整计费号码、IMSI、PDP 地址、SGSN/GGSN/Charging Gateway IP、用户位置等明细。

指标分为三类：

- **真实聚合**：能由话单字段直接计数、去重或求和复算；
- **规则推导**：由真实字段按明确规则计算，或取自报告中的规则模型结果；
- **情景假设**：源数据完全没有对应字段或业务口径，只能用于讲解“如果采用某假设会得到什么结果”，不得作为真实经营结果。

当前文件标称周期为 `2026-07`，但事件时间实际覆盖 `2026-06-04` 至 `2026-08-01`。页面默认选择“全量样本”，因此全量 KPI 包含跨期记录。

## 4. 完全没有数据支撑、仅作情景假设的参数

| 参数 | 当前处理 | 假设 / 公式 | 为什么没有真实支撑 |
|---|---|---|---|
| 结算单价 | ¥5 / GB | 用户指定展示口径：1 GB 按 5 元计算 | Excel 没有资费、批价、币种或结算协议字段 |
| 情景结算支出 | 全量约 ¥110.30 | 23,685,836,196 B ÷ 1,073,741,824 × ¥5 / GB | 只有流量是真实值，单价及金额不是实际结算结果 |
| 情景结算收入 | ¥0 | 仅表示“本样本无香港用户在广东方向记录” | 不能解释为真实业务收入为零 |
| 情景结算净额 | 全量约 -¥110.30 | 情景收入 - 情景支出 | 不代表财务口径、应收应付或损益 |
| 用户“流量指数”刻度 | 100 分制视觉刻度 | `100 - 当前榜单名次` | 只有排名来自真实流量；100 分制刻度没有收入、转化或标签样本校准，不是模型评分 |

以下旧版指标因完全没有数据支撑，已从页面删除或改写：双方 CDR 流量差异、双方计费金额差异、真实结算收入/支出、预计可追回金额、节省人工工时、待处置工单、实时链路延迟、话单缺失和生产 AI 风险评分。

## 5. 筛选口径

- “全量样本”：33 个有记录的数据日，31,410 条记录；
- “近 30 天”：按最后 30 个自然数据日窗口，2026-07-03 至 2026-08-01，共 29,409 条；
- “近 14 天”：2026-07-19 至 2026-08-01，共 13,409 条；
- “近 7 天”：2026-07-26 至 2026-08-01，共 6,409 条；
- “香港 → 广东”：当前样本返回 0，并明确提示“本样本无记录”，不外推真实业务量。

KPI 卡不再生成“较上期增长率”，因为源文件不足以为所有筛选周期提供等长、可比且未受抽样上限影响的上一周期；页面显示“样本快照”。

## 6. 数据质量与公开发布边界

1. 文件标称月份和事件月份不完全一致，应在 DataEase 入库时增加账期字段与事件时间校验。
2. 31,408 条记录集中在 00 点，工作时段、夜间使用和商务行为结论均不可直接采用。
3. 30 天每天恰好 1,000 条，趋势只能描述“当前样本”，不能证明生产全量趋势。
4. `结论.docx` 中“PLMN 全部为 45403”应更正为 45403 共 31,407 条、45404 共 3 条。
5. GitHub Pages 只提交本仓库中的脱敏聚合 JSON 及中间四位掩码号码；不得提交原始 Excel、原始 Word 提取物、完整号码、IMSI、IP、PDP 地址或位置明细。

## 7. 后续 DataEase 接入建议

优先建立三层数据集：原始受控明细层、脱敏用户/日聚合层、大屏指标层。大屏只读取指标层；金额类指标必须等到资费表、结算方向、币种、账期和对侧核对数据到齐后，才能从“情景假设”升级为“规则推导”或“真实聚合”。
